## 功能与设计背景

> 默认情况下，本 Mod 所加入的的女仆的 AI 自言自语和主人登录欢迎语，每次都会实时调用 AI 生成，产生一次真实的 API 请求。但是在实际使用中会发现：在相似场景下的女仆自言自语/欢迎语内容其实经常差别不大。因此，本 Mod 新增了一个可选的「预制复用」功能，允许女仆将曾经生成过的自言自语/欢迎语内容进行存储，在存储数量足够且环境条件重合时，可以直接复用曾经生成过的内容，减少 API 请求带来的成本。
>
> 同时，此功能也提供了自定义内容的路径，玩家可以为女仆设计自己的自言自语/欢迎语内容，来获得更稳定的对话体验。

开启「预制复用」后：

- 女仆**调用 AI 真实生成**出自话/欢迎语时，Mod 会把这条内容**自动存进世界里的内容库**（连带当时的环境条件、女仆人设、语言等核心信息）。
- 之后遇到**环境条件足够相似**的自话/欢迎语触发时，Mod 会优先从内容库中根据环境条件等进行匹配：若匹配条目足够多，就直接使用已有内容，**跳过本次 AI 生成**，响应更快，也省下 API 调用。
- 为了避免一直在有限的内容中复读，本 Mod 默认设置在匹配数量满足时，仍会有 40% 的请求会进行真实的 API 调用，为内容库注入新鲜血液
- 你也可以**自己手写条目**放进 `custom/` 目录，让女仆在指定场景下说出你写好的台词——比如固定的节日问候、特定天气的吐槽、服务器专属梗等。手写条目的格式见下文；

此功能目前**只作用于自言自语和登录欢迎语**，玩家和女仆的正常聊天、女仆互聊都不会使用预制内容。功能默认关闭，需要手动开启。

## 快速启用

1. **打开女仆设置界面**：在 TLM 的 AI 聊天界面左侧按钮组末尾，点「💬」小按钮进入「女仆设置」页；
2. **打开复用面板**：在设置页右侧 Prompt 面板下方，点「预制复用」按钮，弹出复用设置浮层；

![玩家设置界面中的预制复用入口](pictures/player-settings-entry.png)

3. **选择启用范围**：在浮层里打开「复用 全局默认」（你名下所有女仆都用），或把某一只女仆单独设为「强制开」。

## 环境信息匹配机制

> Mod 会把「这只女仆是谁（名称+人设）」「现在是什么环境（天气、时间、事件等）」和预制内容库中的已有条目进行对比，条件满足的内容会进入随机池，发送预制内容时会从随机池中抽取。

- **按人设区分**：同一只女仆（同名+同人设）共用一份内容库。只要对人设/女仆名称进行修改，就会产生一个新的内容库，旧的内容库会保留在存档中，但不再参与匹配，除非出现一只新的，名字与人设与此库所记录的女仆完全一致的女仆。
- **单条目内精确匹配**：比如`时间`环境变量条目记录了「夜晚」，那么当某次触发时为「白天」时，就会视为此变量条目未命中。
- **多条目选择性匹配**：当记录的环境变量等条目较多时，只要有**至少4个条目**达成**单条目内精确匹配**，此条内容便可视为命中。

## 玩家设置

复用设置面板分上下两部分：

![复用设置面板整体界面](pictures/reuse-panel-overview.png)

「个人设置」区（所有人可见）：

- **复用 全局默认**：玩家自己的总开关，默认关闭。开启后，此玩家名下所有没有单独设置过的女仆都会启用；
- **复用 本只女仆**：每只女仆可以单独设为「跟随默认 / 强制开 / 强制关」。

管理员开放个人参数设置后，这里还会多出「跟随服务器默认配置」的勾选框和两个数值输入：

- **跟随服务器默认配置**：勾选时使用服务器的全局参数；
- **最低可用条数**：合格候选条数低于该值时不会复用，直接真实生成。
- **使用预制内容的概率**：候选充足时按此概率决定是否复用，未命中照常真实生成。

管理员在配置里禁用玩家选项时，玩家之前保存的参数不会被删除，但是也不会生效。

## 管理员设置

「服务器设置」区仅管理员可见（OP ≥ 2 ），可以调整：

![复用面板的服务器设置区](pictures/server-settings-section.png)

- **服务器默认最低可用条数**（默认 8）：
  	当前环境下候选条目达到这个数量，才有可能使用预制内容。
    	调低 → 更容易触发预制内容；
    	调高 → 只有某个环境的所处时间较长时才有较大可能使用预制内容。
   
- **服务器默认使用概率**（默认 60%）：

    调低 → 更容易触发预制内容；
    调高 → 更倾向使用 AI 真实生成。

- **允许玩家自定义预制复用参数**：是否允许玩家自己覆盖上面两个值。关闭时会重置所有人的「跟随服务器默认配置」状态（个人调整的参数数值仍然保留，但重新开放后需要玩家再次手动取消跟随）。

另有两个**配置文件**项（`config/maid_self_talk-common.toml` 的 `prebuilt_reuse` 段，不在游戏内管理员界面里，只能改配置文件），仅适用于高级需求，通常不需要改动：

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `minMatchingContexts` | 4 | 一条条目要被视为候选，至少要有几个环境条件与当前完全一致 |
| `maxEntriesPerSource` | 300 | 每个女仆内容库每个来源（欢迎语/自话）的容量上限，超出后淘汰最旧的机器条目（custom 条目不纳入此计算） |



## 自定义预制内容

这是本功能最有可玩性的部分：**手写自定义台词库**。也是本文档的主要介绍内容。

### 目录位置

本功能产生的文件储存在世界存档内，

文件结构如下：

> `<世界存档>/data/maid_self_talk/prebuilt/`下带有`generated`前缀的为机器自动生成内容，请勿随意编辑。
>
> 面向用户自定义的文件夹为`<世界存档>/data/maid_self_talk/prebuilt/custom/`。

```
<世界存档>/data/maid_self_talk/prebuilt/custom/		← 请注意此处为custom/
├── _global/                    ← 对所有女仆生效
│   ├── welcome/                ← 欢迎语(登录时)
│   │   └── *.md
│   └── self-talk/              ← 自言自语
│       └── *.md
└── <女仆显示名>/                ← 只对这只女仆生效(女仆在游戏里叫什么(支持命名牌命名)就建什么目录)
    ├── welcome/
    │   └── *.md
    └── self-talk/
        └── *.md
```

请注意：

- 本 Mod 只使用 `welcome/` 和 `self-talk/` 目录**顶层**的 `.md` 文件，子目录文件不会被使用；
- `_` 开头的目录（如 `_global`）是保留名，**不可使用此名作为女仆的名字**；
- `_diagnostics.md` 是 Mod 自动生成的诊断报告，**用于警告用户自定义内容的格式错误等问题，请只读查看，手动编辑无效**；
- 以女仆名字命名的文件夹**没有匹配到任何已加载的女仆**时，会在`_diagnostics.md`诊断报告里列出（方便发现打错名字）；
- 以女仆名字命名的文件夹按「命名牌名称 → 内置模型预置名」的顺序解析女仆名字；
- 使用自定义 YSM 模型时，**若女仆无命名牌名称**，则女仆在聊天框中的名字会显示为模型名，**此名不会作为女仆的名字，无法解析**；
- 修改、新增文件后**重启服务端生效**；`custom/` 文件夹对于 Mod 是只读的——Mod 永远不会修改、删除或往这些文件里写内容，只会生成`_diagnostics.md`作为诊断报告；
- 请务必保证自己的女仆名字与存储其预制内容的文件夹名**逐字一致**，否则无法匹配。

### 条目文件格式

本章节所述文件格式均为 Markdown 格式。

每个 `.md` 文件 = 一条预制内容，由两部分组成：**YAML 头**（`---` 之间，描述环境上下文等匹配条件）和**正文**（实际说出的内容）。

**硬性格式要求**（若不满足要求则视为不合法文件，不会被正常启用，并写入诊断报告）：

1. 必须有 YAML 头（以 `---` 开始和结束）；
2. YAML 头里必须声明 `bodyFormat: "fenced-v1"`。
3. 至少包含 H2 标题`Chat`且正文必须采用 Markdown 格式的代码块包裹

一个最小的可用示例：[minimal-example.md](attachment/minimal-example.md)

正文必须放在 `## Chat` 和 `## TTS` 两个段里，每段用一对 ` ``` ` 反引号代码块包裹：

- `## Chat`：聊天栏/气泡显示的文字（必填）。
- `## TTS`：语音合成读的文本（可选；缺失时 Mod 会直接用/翻译 Chat 文本进行一次 TTS 请求来生成语音）；

代码块之外不允许写其他零散文字内容。

### 完整示例

一条「下雨天的自言自语」，对全服女仆生效，放在 `custom/_global/self-talk/rainy-day.md`：

[rainy-day.md](attachment/rainy-day.md)

一条「只对你的女仆『小铃』生效、仅中文环境的清晨欢迎语」，放在 `custom/小铃/welcome/good-morning.md`：

[good-morning.md](attachment/good-morning.md)


> 说明：上面的 env key 名称（`weather` / `game_time` 等）与取值是**示例取值**，实际可用的环境 key 以你服务端生成的 `custom/_diagnostics.md` 报告末尾附带的「环境 key 目录」为准。

### env 环境条件怎么写

- 单条 `env` 内有几个 key，就要求触发时**全部**与实际环境一致；
- **无环境约束/通用**：不写 `env` 或写 `env: {}` 表示**任何环境**都可以命中；
- YAML 头里不写 `chatLanguage`，表示语言通用（任何语言均可用），若写了则触发时玩家所使用的语言必须与所写语言一致；
- `env` 的 key 或值写成非法形式（比如显式空值、列表、嵌套结构）会导致该条被拒绝/跳过，诊断报告中会说明原因。

### 格式出错怎么办

- Mod 读取到格式有问题的条目会跳过，原文件会原样保留，按报告里的说明和样例改正后重启游戏即可恢复。
- 所有报错条目都会写入 `custom/_diagnostics.md`，可自行查阅、核对、修复。

![custom/_diagnostics.md 诊断报告内容](pictures/diagnostics-report.png)

- 如果某个有名字的女仆目录下有报错，这位女仆的主人在**本次游戏/服务端运行过程中首次上线**时会收到一条私信提醒，提醒玩家及时处理。

![主人上线时收到的诊断提醒私信](pictures/login-warning-message.png)

## 自动生成条目

开启复用后，每次真实生成成功（且当时复用开关仍有效），Mod 自动把新内容存为机器条目：

```
<世界存档>/data/maid_self_talk/prebuilt/generated/
├── welcome/v1-<人设指纹>/entry-<UUID>.md
└── self-talk/v1-<人设指纹>/entry-<UUID>.md
```

机器条目同样是 YAML 头 + 正文的格式（规范相对更严格），会记录当时抽中的全部环境条件、语言、人设、创建时间。**可以打开看内容，但不建议手动编辑**——它是 Mod 自己管理的内容库；想写自己的内容请用 `custom/`。

容量管理：

- 每只女仆、每种类型各自计数，默认上限 300 条。
- 条数达到上限时会自动淘汰**最旧**的机器条目；
- custom/ 手写条目不会纳入上限计算范围，不会被自动删除。

## 预制语音缓存（可选）

### 自动缓存

默认情况下，即使命中预制条目，TTS 语音仍是实时调用合成接口生成的。**管理员**可以在游戏内设置面板打开「**保存并复用预制语音**」（默认关闭）来开启预制语音缓存功能：

- 打开后，真实合成的语音会自动按「音色+语言」进行区分，缓存到 `prebuilt/generated-audio/`；
- 下次命中同一条目、且当前音色和语言一致时，**直接播放缓存音频**；
- 关闭开关只停止新的缓存与命中播放，**不会删除已有音频文件**。

![复用面板中的「保存并复用预制语音」开关](pictures/prebuilt-audio-toggle.png)

### 人工放置音频

你还可以给`custom`条目**自定义配音**：

- 把音频文件放在 `.md` 文件条目**同目录**、与条目**同名**（即为与其所对应的 `.md` 文件仅文件后缀名不同）
  例如为`good-morning.md`存储的预制语音有效文件名为 `good-morning.mp3`；
- 人工音频默认**不识别语言是否一致**，直接使用，优先级最高；
- 同时存在 `.mp3` 和 `.ogg` 时优先播 MP3；
- 目前仅支持 MP3、Ogg Opus、Ogg Vorbis 三种格式。

![custom 条目与同名音频文件并排](pictures/entry-and-audio-files.png)

## 常见问题 FAQ

**Q：开了预制内容，女仆是不是就不再说新内容了？**<br>
A：不是。候选条数要凑够「最低可用条数」、还要过「使用概率」这一关，默认 60% 意味着仍有 40% 的触发会实时生成新内容（并继续丰富内容库）。把概率调成 100% 才是尽最大可能复用旧内容。

**Q：为什么我写的 custom 条目不生效？**<br>
A：首先打开 `custom/_diagnostics.md` 看告警，通常能直接定位原因，也可按顺序排查：
① 文件路径是否在 `custom/<女仆名>/{welcome 或 self-talk}/` 顶层；<br>
② YAML 头是否完整且有 `bodyFormat: "fenced-v1"`；<br>
③ 正文是否在 `## Chat` / `## TTS` 的反引号围栏里；<br>
④ env 条件是否和当前环境对得上；<br>
⑤ 改动后是否重启了服务端。

**Q：改了女仆人设后，之前积累的内容库还在吗？**<br>
A：在存档中保留，但不再参与匹配（人设变了就是另一只「她」）。改回原来的人设即可恢复使用旧库（也可以复制旧库文件，但是肉眼很难识别具体对应了哪只女仆）。

**Q：custom 条目会被因为触碰到存储上限而被自动删除吗？会被 Mod 改写吗？**<br>
A：都不会。Mod 对于手写条目只读。

**Q：这个功能会影响正常聊天或互聊吗？**<br>
A：完全不影响。它只作用于自言自语和登录欢迎语，并且可以关闭。

**Q：命中预制内容后还会产生 TTS 模型请求吗？**<br>
A：会。条目自带 TTS 段，语言与当前目标 TTS 语言不同时会自动做一次简短的翻译再合成；翻译失败就只显示文字、不播错误语言的语音。开启预制语音并命中预制语音时，则直接播放预制语音。

**Q：服务器换 TTS 音色后，缓存的语音还能用吗？**<br>
A：自动缓存按「供应商+音色+端点+语言」区分，换了音色会建立新的缓存目录，旧缓存保留但不再命中；人工放置的音频不受音色影响，始终可命中。
